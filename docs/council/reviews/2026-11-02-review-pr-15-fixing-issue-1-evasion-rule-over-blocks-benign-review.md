# Review PR #15 fixing Issue #1: Evasion rule over-blocks benign sub-steps and ... Review

## Scope reviewed

The council reviewed commit range `0ec1b5632812d1eea410e023349b57b62a61d428..b4c4a71de5bc675bb6ec5ed660b1ee7fe519d918` on PR #15 across all six modified files (`aegys/command_checks.py`, `aegys/guard.py`, `aegys/shell_words.py`, `tests/test_command_checks.py`, `tests/test_guard.py`, and `tests/test_shell_words.py`), together with surrounding context in `README.md` and `aegys/data/default-config.json`. All four council seats (`chair`, `reviewer` on Mistral Large 4, `critic` on GLM 5.3, and `saboteur` on Pro) read and judged all six files across two rounds; `saboteur` additionally ran the 103-test targeted suite and executed 6 fault-injection mutations (3 in Round 1, 3 in Round 2) in isolated throwaway worktrees.

## Strengths

- `aegys/shell_words.py:99-104` and `aegys/command_checks.py:867-872` resolve the `for`-loop false write cleanly: `unwrap` drops the loop variable while retaining `in WORDS...` attached to `for`, and `READ_ONLY_PROGRAMS` marks `for`/`select`/`case` as read-only so `program_writes` (`aegys/command_checks.py:1166`) is `False` while `bash_path_denial` (`aegys/command_checks.py:1505-1507`) still inspects every word for secret paths. `saboteur` confirmed in Round 2 Mutation 2 that removing `"for"` from `READ_ONLY_PROGRAMS` (`aegys/command_checks.py:870`) is caught by `tests/test_command_checks.py:42-67`.
- `aegys/guard.py:1497-1545` retries Stage 1 (`fast` `0`/`1` classifier) once on malformed text or unclean `stop_reason` before failing closed, and `saboteur` confirmed in Round 1 Mutation 3 (`range(2)` -> `range(1)` at `aegys/guard.py:1502`) that `tests/test_guard.py:1507-1542` catches the fault.
- `aegys/guard.py:856-912`, `1008-1026`, and `1627-1634` preserve all deterministic security boundaries (hard-deny, critical-path, secret-path, and control-file checks return before `classifier_decision` at `aegys/guard.py:1917-1953`) while surfacing `tier` and `before latest user message` turn boundaries to the classifier and suppressing automatic repeat-strikes across a new user message.

## Issues

- [critical] `aegys/shell_words.py:99-102`: `unwrap` returns `[], None` for any `for`/`select` header whose third word is not `"in"`, dropping the loop body when `do` follows `for NAME` without a semicolon (`for f do rm -rf ~; done`). Confirmed by `chair`, `reviewer`, and `critic` (`critic` demonstrated that pre-PR `unwrap` fell through and left `["for", "f", "do", "rm", "-rf", "~"]` intact for `deletes_in` at `aegys/command_checks.py:620-626`, making this a deterministic security regression). Fix: when `len(words) >= 3 and words[2] == "do"`, delete `words[:3]` and `continue` the `unwrap` loop so the body is unwrapped as a stage.
- [critical] `aegys/command_checks.py:489-495` (with `436`, `443`): Command substitutions are evaluated once after the outer stage loop using only the final `current` directory, drop the session `cwd`, reset `known = True` inside the recursive `command_stages` call (`aegys/command_checks.py:443`), and run after `heredoc_bodies` (`aegys/command_checks.py:436`) has stripped unquoted heredoc bodies. Graded `[critical]` by `chair` and `reviewer` and `[important]` by `critic` (kept at `[critical]`; `critic` argued missed detections inside `$(...)` improve on the pre-PR baseline and the false deny requires a substitution followed by `cd`, whereas `chair` and `reviewer` graded the false secret deny on `echo "$(cat config)" && cd ~/.ssh && ls`, the lost `cwd_known` after `cd "$unknown"`, and unquoted heredoc `cat <<EOF\n$(rm -rf ~)\nEOF` as merge-blocking). Fix: extract command substitutions per stage (and from unquoted heredoc bodies) using that stage's `cwds` and `cwd_known`, passing both into recursive `command_stages` calls.
- [important] `aegys/guard.py:1627` and `tests/test_guard.py:1498-1620`: `saboteur` Round 1 Mutation 1 (`clear_strikes = False` at `aegys/guard.py:1627`) survived all 143 tests because `test_evasion_rule_compares_risky_action_and_clears_on_post_deny_user_permission` never asserts that `state["strikes"]` is reset to `0` or that `strike_at` is removed after an `explicit_intent` allow. Fix: add `saboteur`'s regression test `test_explicit_user_intent_clears_strike_counter_and_timestamp` asserting `state["strikes"] == 0` and `"strike_at" not in state`.
- [important] `aegys/command_checks.py:396-409` and `tests/test_command_checks.py:68-80`: `saboteur` Round 1 Mutation 2 (deleting the backtick command-substitution branch at `aegys/command_checks.py:396-409`) survived all 143 tests because `test_write_inside_command_substitution_is_still_denied` only tests `$(...)`. Fix: add `saboteur`'s regression test `test_write_inside_backtick_command_substitution_is_still_denied` covering `` `...` `` command substitutions across `agy_bash_control_denial`, `critical_removal`, and `bash_path_denial`.
- [important] `aegys/guard.py:1017` and `tests/test_guard.py:1608-1620`: `saboteur` Round 2 Mutation 1 (changing `e.get("tier") in ("soft_deny", "evasion")` to `("soft_deny",)` at `aegys/guard.py:1017`) survived all 143 tests because the existing test only exercises cross-turn repeats after a `soft_deny`, never after an `evasion` deny. Fix: add `saboteur`'s regression test `test_evasion_deny_repeated_after_new_user_message_is_not_auto_strike`.
- [important] `aegys/command_checks.py:353-366` and `tests/test_command_checks.py`: `saboteur` Round 2 Mutation 3 (deleting the `$((` arithmetic expansion skip at `aegys/command_checks.py:353-366`) survived all 143 tests because no test exercises `$((...))` arithmetic expressions, and without that branch `$(( (1 + 2) * 3 ))` is misparsed as phantom command stages `['1', '+', '2']` and `['*', '3']`. Fix: add `saboteur`'s regression test `test_arithmetic_expansion_with_subexpressions_does_not_break_stage_parsing`.
- [important] `aegys/command_checks.py:240-245`, `1187-1211`, and `1396-1413`: `reads_program_from_stdin` checks `"-" in args` anywhere in `words[1:]` rather than checking whether `-` is the interpreter's script operand, and `stage_paths` resolves inline-code strings (`stage.inline_code`) as filesystem paths. Graded `[important]` by `chair`; `reviewer` and `critic` noted that `reads_program_from_stdin` was not modified in PR #15's diff and would treat it as a separate follow-up, while `chair` noted it directly causes `aegys` false-denies on `python3 script.py - <<'EOF'` when heredoc data mentions control spellings or secret-path substrings. Fix: in `reads_program_from_stdin`, treat `-` as stdin-program only when no script/module/`-c` operand precedes it; in `stage_paths`, skip `stage.inline_code` words and strings containing newlines.
- [minor] `aegys/command_checks.py:353-368`: `command_substitutions` skips arithmetic expansion `$((...))` bodies without recursing into them (`critic`, `reviewer`), so a quoted arithmetic expression containing a command substitution (`echo "$(( $(rm -rf ~) ))"`) is not walked deterministically. Fix: recursively extract `command_substitutions` from the slice inside `$((...))`.
- [minor] `aegys/command_checks.py:370-395`: `command_substitutions` does not track backticks inside a `$(...)` scan (`reviewer`, `critic`), so a `)` inside backticks (`echo $(rm \`echo )\` -rf ~)`) closes the `$(...)` scan early. Fix: when scanning inside `$(...)` outside single quotes, skip over backtick-quoted spans before counting `(` / `)`.
- [minor] `aegys/command_checks.py:426-433`, `aegys/guard.py:36-41`, and `README.md:31`: Docstrings and `README.md` do not mention that `command_stages` walks `$(...)`/backtick substitutions or that evasion checks compare the denied risky operation and clear on post-deny `explicit_intent` user authorization (`reviewer`, `critic`). Fix: update those three documentation sites.
- [minor] `aegys/guard.py:858-867` and `901-903`: Pre-upgrade state entries lack `user_turn` so they age out over one turn (`critic`, `reviewer`), and `clear_strikes` resets the per-conversation strike counter rather than a per-goal counter (`reviewer`, `critic`). All participants agreed these are acceptable trade-offs of the minimal state schema.

## Recommendations

- Implement both `[critical]` parser fixes (`for NAME do CMD` unwrapping in `aegys/shell_words.py:99-102` and per-stage `cwds`/`cwd_known` + unquoted heredoc command substitution scanning in `aegys/command_checks.py:489-495`), the `[important]` `reads_program_from_stdin` / `stage_paths` fix, the `[minor]` `$((...))` recursion, backtick-in-`$(...)` tracking, and docstring updates, and all four surviving-mutant regression tests identified by `saboteur`.
